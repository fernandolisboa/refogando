## 2. Landmines e gotchas de ambiente

- **Rota nova sob `src/app/[locale]` precisa entrar em `CLIENT_ROUTE_TREE`** (`src/domain/error-report.ts`). O teste da allowlist reprova até entrar; sem isso a rota sairia como `[param]` no log.
- **Não interpolar dado de usuário em `throw new Error(…)` no cliente**, nem em `code` de erro próprio no servidor. A sanitização da mensagem é heurística: nome próprio solto, sem aspas nem `@`, passa.
- **O relato só liga com `NODE_ENV === 'production'`.** Em `next dev` e no Vitest é no-op; os testes ligam com `{ enabled: true, send }`. No E2E (`next start`) está LIGADO: um erro de página lá já reprova pelo guarda de console, e o POST para `/api/client-errors` é localhost (não fere o guarda de rede).
- **O relato nunca pode escrever no console do navegador** (o guarda do E2E reprova e um log viraria relato). O teste `client-error-report.test.ts` falha se algum `console.*` for chamado.
- **`src/app/global-error.tsx` é pré-renderizado no build:** nada de `window`/`location` no render; o locale vem do `useLocaleFromPath` (snapshot de servidor `DEFAULT_LOCALE`). O default export se chama `RootGlobalError` (`GlobalError` é o de `[locale]/error.tsx`).
- **`[?]` não serve como marcador de rota:** o `?` vira query na re-normalização do servidor. O 1º segmento desconhecido sai `[sem-locale]`.
- **Locale do caminho é texto do usuário:** `canonicalLocale` usa `Map` (antes um objeto literal: `/constructor/…` achava `Object` e derrubava o `global-error`). Lookup novo por segmento de caminho usa `Map` ou `Object.hasOwn`.
- **Ferramenta de edição e `\uXXXX`:** ao escrever regex com escapes Unicode por ferramenta, confira que o arquivo ficou com o escape e não com o caractere cru (U+2028 cru dentro de regex literal quebra o parse). Os testes montam esses caracteres com `String.fromCharCode`.
- **Vitest com `ErrorEvent`:** sem nenhum listener de `error` na janela, o Vitest trata um `ErrorEvent` com `error` como exceção não pega. Teste que dispara depois de remover os listeners usa só `message`.
- Rodar Vitest: `flock /var/tmp/vitest.lock env TEST_DATABASE_URL=… TEST_DATABASE_URL_UNPOOLED=… npx vitest run` (variáveis inline, nunca `export`). Os testes novos rodam sozinhos com `npx vitest run --project ui <arquivos>`, sem banco.
