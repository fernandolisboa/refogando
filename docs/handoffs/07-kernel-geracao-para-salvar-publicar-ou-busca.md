## Estado (o que #8 deixou no `main` — referência, **não reimplementar**)

Tudo verde no `main` (`npm test` **179/179** contra Postgres real; `lint`/`typecheck`/`build` limpos). Construído **em cima da espinha #3 + auth #5 + locale #4**. Ponteiros (detalhe no diff do PR #32):

- **Geração é uma chamada constrita pelo seam.** `src/server/claude/client.ts`: a interface `ClaudeClient` ganhou `generateRecipe(input): Promise<GenerationOutput>`. `RealClaudeClient` usa **`client.messages.parse({ model, max_tokens, messages, output_config: { format: zodOutputFormat(RecipeGenSchema) } })`** (SDK `@anthropic-ai/sdk@0.104.1`), ramifica por `message.stop_reason` (`refusal`/`max_tokens`) e lê `message.parsed_output`. `FakeClaudeClient(reply?, canned?)` injeta um `GenerationOutput` enlatado em teste. **A API real só é tocada no `RealClaudeClient` — NUNCA em teste.**
- **Schema canônico de geração é um OBJETO PLANO**, não discriminated union. `src/domain/recipe-gen-schema.ts` (`RecipeGenSchema` = `z.object({ kind: z.enum([4 valores]), receita: ReceitaGen.nullable(), advisory })`). **Landmine crítica:** a API de structured outputs **rejeita** `z.discriminatedUnion`/`anyOf` com `$defs` (`output_config.format.schema: For 'anyOf', '$defs' is not supported`) — descoberto por um round-trip real no micro-spike. A regra **`kind=impossible ⇒ receita null` é de APP** (no `classify`), não imposta pelo schema. **#11/#12 reusam esse mesmo schema — mantenha plano.**
- **`classify()` é o ponto único de validação** (`src/domain/generation.ts`, puro): mapeia o `GenerationOutput` cru na taxonomia `success|degraded|playful|impossible|invalid`. Valida **no app** (não no modelo): `porcoes`/`dificuldade` (faixas), `quantidade` do ingrediente (regex `numeric(10,3)`), `originalLocale` (`isSupportedLocale`). Qualquer fora-de-faixa/lixo → `invalid` (não clampa). `refusal`/`max_tokens`/`parse_failed` → `invalid`.
- **Taxonomia → persistência** (`src/server/generation/persist.ts`, uma transação): `success/degraded/playful` → Receita **privada** (`origin ai_chat|ai_structured`, `owner_id=usuário`, `visibility=private`) + translation (`provenance='automatica_nao_revisada'`) + ingredientes (`quantidade` STRING, `ingredient_id` NULL) + `creation_session` + `generation`. `impossible` → `creation_session` + `generation` (`recipe_id` NULL), **sem Receita**. `invalid` → **persiste NADA**.
- **Tabelas novas (migração `drizzle/0003_fluffy_human_torch.sql`, idx 3):** `creation_session` (`user_id` NOT NULL→users cascade; `mode` pgEnum `creation_mode` em **inglês** `conversation`/`structured`; `recipe_id` NULLABLE→recipe set null = ref **fraca** sessão→receita, ADR-0006); `generation` (`outcome` pgEnum `generation_outcome` **próprio, 5 valores** = separado de `result_kind` que segue 3; `advisory_comment` = Comentário consultivo **fora** da Receita; `model`, `schema_version`, `recipe_id` NULLABLE set null). `CREATION_MODES` em `src/domain/recipe.ts`, `GENERATION_OUTCOMES` em `src/domain/generation.ts`.
- **Rotas (ADR-0010, `runtime='nodejs'`):** `POST /api/generations` (requireSession; valida input fora-de-faixa **antes** do seam → 400; modelo de `app_config.default_model`; classify → `invalid` 502 sem persistir, `impossible` 200, `success/degraded/playful` 201 com `recipeId`). `GET /api/creation-sessions/[id]` (retomada: 404 sem vazar dono; devolve a Receita atual mesmo com `schema_version` antigo, sem migrar).
- **Gate de visibilidade (blocker fechado nesta fatia):** `GET /api/recipes/[id]` agora gateia Receita **privada** (só o dono lê; 404 sem vazar existência); catálogo (`owner_id NULL`) e `public` seguem abertos. O loader foi extraído pra `src/server/recipe/load.ts` (`loadRecipeRows`, compartilhado com a retomada); helper de params em `src/server/http/params.ts`.
- **`app_config.default_model`** (da #5) agora vira **efeito real**: a rota de geração consome esse valor.

## Processo (inegociável — funcionou em #3/#4-#5/#8, manter)

Os 8 passos rodam **cada um num subagente fresco** (**Agent** para um passo; **Workflow** para fan-out/pipeline). O loop principal **só orquestra e integra**. Padrão que rendeu nesta sessão (replicar): 1. **Explorar** → Workflow de leitores paralelos (issue/ADRs/CONTEXT/código/seam) + síntese num brief que **separa o que congela schema (grelhar) do reversível (decidir+porquê)**. 2. **Planejar** → Agent escreve plano file-by-file (rascunho em `docs/plans/`, **removido antes do commit**). 3. **Revisar o plano** → Workflow multi-lente + **verificação adversarial de cada achado** + síntese com emendas. 4. **Corrigir o plano** → Agent. 5. **Implementar** → Workflow: **backbone serial** (deps + schema/migração + **micro-spike** que valida a integração arriscada contra Postgres real ANTES do fan-out) → **fatias paralelas em arquivos disjuntos** → **green-gate único** que itera até verde. 6. **Code-review** → Workflow: lentes (correção/segurança/qualidade/perf/ADR+CONTEXT/migração) → verificação adversarial → síntese. 7. **Corrigir** → Workflow: fixes em arquivos disjuntos + re-green-gate. 8. **Validar e fechar** → orquestrador: validação autoritativa no loop principal; remover rascunho; branch a partir do `main`; commit; push; PR; **squash-merge**; fechar issue.

**Lições desta sessão:** (a) o **micro-spike pagou de novo** — o round-trip real provou que o discriminated-union é rejeitado pela API e o flat-object é aceito, evitando um bug tardio (sem o spike, só descobriria no `RealClaudeClient`, que nenhum teste exercita); **faça o spike tocar a integração arriscada de verdade, não só compilar**. (b) **Síntese de Workflow com schema falha** se o input for grande demais (o agente não chama `StructuredOutput`) — blindei com input trimado + "você DEVE chamar a tool" + `try/catch` que devolve os achados crus; replicar esse padrão em qualquer passo de síntese. (c) **Code-review adversarial** descartou 11 falsos-positivos (ex.: "API key vazada" era só `.env.example` comentado) e confirmou 1 blocker real (gate de visibilidade) + 1 major (quantidade não-numérica → 500 em vez de 502). (d) Em fatia sem UI, o "verify de browser" não se aplica — o contrato é testado via `FakeClaudeClient` + integração na porta alta.

## Mapa de propriedade / landmines (para a próxima fatia)

- **Schema de geração é PLANO de propósito** (a API rejeita `anyOf`+`$defs`). Se #11/#12: NÃO transforme `RecipeGenSchema` em discriminated union. A cross-field rule mora no `classify`.
- **`result_kind` segue congelado em 3 valores** (`success|degraded|playful`); `impossible`/`invalid` só existem em `generation_outcome`. **Nunca** insira `impossible`/`invalid` em `recipe.result_kind`.
- **`playful ⇒ private`** é CHECK no banco (`recipe_playful_private_chk`, 23514). Para #13: **publicar uma Receita `playful` deve ser recusado** (é zoeira, não publicável — CONTEXT). A Receita nasce `private`; #13 só muda `visibility` quando permitido.
- **`origin` é imutável (trigger P0001 no UPDATE).** Publicar muda `visibility`, **não** `origin`. Visibility e origin são eixos ortogonais (ADR-0002/0003).
- **Persistir/publicar exigem conta** (ADR-0011): `requireSession`/`requireRole` (`src/server/auth/guard.ts`). Visitante gera efêmero (não persistido); **salvar/publicar é da conta do dono**.
- **Gate de visibilidade já existe** (`recipes/[id]/route.ts`): privada só pro dono, catálogo/pública abertas. #13 estende o ciclo de publicação, não reimplementa o gate de leitura.
- **#7 (se escolhida):** ADR-0004 — Aviso **honesto e amigável**, **sem gating**, sem suprimir selo, sem travar publicação. Alérgeno no ingrediente é opcional/oportunista. Lógica pura → unit sem DB.
- **#6 (se escolhida):** FTS por idioma + `unaccent` aplicados **idênticos** em build-de-índice e query (senão o GIN é ignorado); seccionar por **origem** (catálogo vs comunidade) **antes** do ranking; nunca cria. Semântica/pgvector é #14, não puxar aqui.
