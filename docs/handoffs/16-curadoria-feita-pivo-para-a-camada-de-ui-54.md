## Processo (inegociável — funcionou em #3..#23..#19; **adaptado pra UI**)

Os 8 passos rodam **cada um num subagente fresco** (**Agent** para um passo; **Workflow** para fan-out/pipeline). O loop principal **só orquestra e integra**. Padrão validado nesta sessão (replicar), com adaptações de UI:
1. **Explorar** → Workflow de leitores ∥ (spec da issue de UI / casca i18n da #4 / catálogos de mensagem / rotas-a-consumir / estado do Next+Tailwind+Playwright / convenções de App Router) + síntese separando o que **congela contrato/design-system** (grelhar) do reversível.
2. **Grill** logo no início — mas: **não há ambiguidade de track** (a próxima é #54, raiz da Wave 1, `Blocked by: None`). Grelhe só o que congela: **direção de design / identidade de marca** (taste — fork real) e a **forma da seam de teste de frontend** (Playwright E2E vs testes de componente). **PREFIRA perguntas abertas em CHAT, não no modal `AskUserQuestion`** (o modal perde texto digitado ao rejeitar — memória `long-form-questions-in-chat-not-modal`). Se o usuário estiver AFK, decida com `/impeccable` + uma identidade sensata de app de receitas e deixe ele redirecionar depois.
3. **Planejar** → Agent escreve plano file-by-file (rascunho em `docs/plans/`, **removido antes do commit**). Pra UI: design tokens, árvore de componentes, shell, estados globais, testes E2E.
4. **Revisar o plano** → Workflow 6 lentes + **verificação adversarial (default=refutar)** + síntese. **SEMPRE verifique claims do review contra o código real** (nesta sessão o review de #19 afirmou "fail-closed" e estava ERRADO; o passo Corrigir refutou).
5. **Corrigir o plano** → Agent aplica as emendas.
6. **Implementar** → Agent; pra UI, construir com a skill **`/impeccable`** (ou `frontend-design`): qualidade de design alta, hierarquia clara, acessível, responsivo, evitando estética genérica de IA. (Pra backend, o micro-spike real contra Postgres ANTES do fan-out segue valendo.)
7. **Code-review** → Workflow multi-lente + adversarial. **#54 EXIGE um subagente especializado de review de FRONTEND que TAMBÉM use `/impeccable`** (hierarquia, espaçamento, tipografia, contraste, estados, responsividade) além das lentes usuais (bugs/segurança/ADR/não-vacuidade). Mutação-verifique cada fix no Corrigir.
8. **Corrigir** → aplica achados + **mutação-verifica** (desligar o fix falha o teste-alvo). **Validar e fechar** → orquestrador: green-gate independente (lint/types/test **+ E2E**) → **`verify`/`run`** pra confirmar no app real (a fatia TEM UI) → remover plano → commit (`Closes #N`) + push → PR → esperar `checks` verde → squash-merge → fechar issue → apagar branch.

**Não há gate de review humano** (memória `afk-means-no-human-review-gate`): plano e código são revisados pelos subagentes especializados (plan-review e code-review/frontend-review), não roteados pro usuário. O usuário decide **track/forks irreversíveis** (e, na UI, **direção de design**) — não revisa diffs.

**Lições desta sessão (#23 + #19):** (a) **A revisão de plano pega bug de segurança/escopo ANTES de uma linha de código** (#19: endpoints de Curador vazariam receita privada sem o gate de comunidade). (b) **O code-review pega testes vácuos, não só bugs** — a mutação-verificação prova que cada novo teste é load-bearing. (c) **Verifique claims do review contra o código** — o review de #19 errou "fail-closed". (d) **Quando o usuário escolhe uma opção sub-especificada** (ex.: "organizar completo" sem a spec definir "organizar"), **esclareça o significado concreto** antes de comprometer (poderia ter virado DDL de coleções desnecessária). (e) **Micro-spike paga** mesmo passando de 1ª (#19: confirmou que o trigger de origin imutável é BEFORE UPDATE, então INSERT catalog passa).

## Gotchas de ambiente (confirmar)

- **`git checkout -- .` antes de implementar** (CRLF/line-endings falsos — memória `phantom-crlf-churn-vs-origin`; `git diff origin/main --ignore-all-space --stat` vazio ⇒ só EOL). Ao stagear: **caminhos explícitos** + **CR=0 E NUL=0** (`python3`); **paths com `[id]`/`[locale]` precisam de aspas** no `git add`. Bytes de controle em regex viram binário — `/[\x00-\x1f]/g`.
- **Branch de `origin/main`** (`git checkout -b <nome> origin/main`). `gh pr merge --delete-branch` falha o delete local → `gh pr merge <N> --squash`, depois `git push origin --delete <branch>` e `git checkout --detach origin/main` antes de `git branch -D` local. Squash-merge pode dar 502 → pollar `gh pr view <N> --json state` até `MERGED`.
- **Check do Vercel FALHA no PR** (não-bloqueante; `gh pr checks` retorna **exit 1** por causa dele). **Gate real** = check **`checks`** do GitHub Actions (hoje typecheck+lint+test; **a #54 deve somar o E2E ao CI**). Main sem branch protection.
- **Issues fecham com `Closes #N`** no corpo do PR (funcionou) ou `gh issue close`.
- **Classificador bloqueia ações externas tangenciais** (abrir issue de follow-up no meio de uma implementação) — registrar no handoff e deixar o usuário decidir/autorizar.
- **`AskUserQuestion` perde texto digitado ao rejeitar** — pra perguntas abertas (direção de design), **use chat** (memória `long-form-questions-in-chat-not-modal`). O modal serve pra escolhas discretas.
- **npm registry** corta pacotes muito novos — **Tailwind / Playwright / qualquer dep de UI na última estável INSTALÁVEL** (testar a instalação). **`ANTHROPIC_API_KEY`** no `.env.local` (gitignored, nunca imprimir).
- **Rascunho de plano** em `docs/plans/` removido antes do commit. **`git push` depois de cada commit.** **Handoffs e PRs sempre via branch** (nunca direto na main). Editar SÓ arquivos canônicos do repo-root.
