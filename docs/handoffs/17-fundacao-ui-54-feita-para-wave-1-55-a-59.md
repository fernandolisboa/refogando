## Processo (inegociável — adaptado pra UI, validado em #54)

Os 8 passos, **cada um num subagente fresco** (`Agent` pra um passo; `Workflow` pra fan-out/pipeline); o loop principal **só orquestra e integra**. Validado em #54:
1. **Explorar** (Workflow ∥): spec da issue / a fundação da #54 a reusar (tokens, primitivos, shell, seam de teste) / a **rota a consumir** (ler o route handler pro shape real de request/response) / convenções de App Router.
2. **Grill** (só o que congela): pra #55–#59 **não há fork de design system** (a #54 já fixou) — grelhe só decisões de **fluxo/UX irreversíveis** se houver, **em CHAT, não no modal** (memória `long-form-questions-in-chat-not-modal`). Se AFK, decida com `/impeccable` + a identidade já estabelecida.
3. **Planejar** (Agent): plano file-by-file (rascunho em `docs/plans/`, **removido antes do commit**); componentes reusando `Container`/botões/tokens, e o **teste de componente jsdom** em `test/ui/`.
4. **Revisar o plano** (Workflow multi-lente + **adversarial, default=refutar**). **Verifique claims do review contra o código** (em #19 o review errou "fail-closed").
5. **Corrigir o plano** (Agent).
6. **Implementar** (Agent) com a skill **`/impeccable`**: alta qualidade, hierarquia/contraste/responsivo/acessível; **reusar os primitivos**; **qualquer cor nova verificada em AA por cálculo**.
7. **Code-review** (Workflow multi-lente + adversarial) **incluindo um subagente de review de FRONTEND que TAMBÉM usa `/impeccable`** (hierarquia/espaçamento/tipografia/contraste/estados/responsividade) além de bugs/segurança/ADR/não-vacuidade. **Mutação-verifique** cada fix.
8. **Validar e fechar** (orquestrador): green-gate independente (**`npm test`** = node+ui, lint, typecheck, **`next build` com `BETTER_AUTH_SECRET`**) → **`verify`/`run` + MCP `playwright`** pra confirmar no app real → remover plano → commit (`Closes #N`) + push → PR → esperar `checks` verde → squash-merge → fechar issue → apagar branch. Ao fim da Wave 1, **`/handoff`** (→ `docs/handoffs/18-*.md`).

**Sem gate de review humano** (memória `afk-means-no-human-review-gate`): plano e código são revisados pelos subagentes especializados, não roteados pro usuário. O usuário decide direção/forks irreversíveis — não revisa diffs.

## Deploy / Vercel (diagnosticado — causa-raiz confirmada e reproduzida)

**Causa-raiz:** o `next build` da Vercel falha em "Collecting page data" porque **`BETTER_AUTH_SECRET` NÃO está setado nas env vars da Vercel**. `src/lib/auth.ts:31-33` lê o secret em nível de módulo (fora do `buildAuth()` memoizado) e **lança** assim que o build importa um route que puxa `@/lib/auth` (o 1º é `/api/admin/roles`), com `NODE_ENV=production` e sem secret (invariante E4, **intencional**). **Não é código** (não é Tailwind/#54 — as falhas predatam a #54; `DATABASE_URL` não é gate de build, `getDb()` é lazy). **Categoria: config de dashboard** → **ação do usuário na Vercel**, não dá pra setar daqui.

**Desbloqueio (o usuário faz):** Vercel → Project → Settings → Environment Variables, em **Production E Preview**: `BETTER_AUTH_SECRET` = `openssl rand -base64 32` (sozinho destrava o build); conferir `DATABASE_URL` (+ `DATABASE_URL_UNPOOLED`) da integração Neon; somar `ANTHROPIC_API_KEY` (e `BETTER_AUTH_URL`) pro runtime. Redeploy.

**Gap registrado → follow-up [issue #68]:** o CI nunca roda `next build`, então falhas só-de-build ficam invisíveis até a Vercel; a #68 propõe somar um build smoke-check (env dummy) ao CI. Reforça o gotcha: prefixe toda build local com `BETTER_AUTH_SECRET=<32+ chars> npm run build`.
